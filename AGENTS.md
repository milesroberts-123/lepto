# AGENTS.md

## Project overview

Snakemake workflow for *Leptosiphon parviflorus* pool-seq analysis (k-mer counting, read mapping, graph genome construction, diversity statistics, functional annotation).

## Commands

```bash
# Dry-run a specific target rule
snakemake -s workflow/Snakefile --profile workflow/profiles/default -n

# Run the full default target (rule all)
snakemake -s workflow/Snakefile --profile workflow/profiles/default --use-conda

# Run a named target rule
snakemake -s workflow/Snakefile --profile workflow/profiles/default --use-conda vg_diversity_all
```

## Architecture

- **`config/config.yaml`** — all workflow parameters (k-mer sizes, BWA settings, vg/grenedalf thresholds, etc.)
- **`config/samples.tsv`** — sample metadata (sample_id, cram_path, group, sample_size)
- **`workflow/Snakefile`** — top-level Snakefile; parses config and samples, defines target rules, includes rule files
- **`workflow/rules/*.smk`** — 20 rule modules: `kmc.smk`, `panther.smk`, `orthofinder.smk`, `featurecounts.smk`, `degenotate.smk`, `vg_diversity.smk`, `dnds.smk`, `sourmash.smk`, `msmc2.smk`, `svim.smk`, `braker.smk`, `freqk.smk`, `anchorwave_pair.smk`, `vigs.smk`, `mcscanx.smk`, `kmate.smk`, `cds_windows.smk`, `ldx.smk`, `busco.smk`, `tubemap.smk`
- **`workflow/envs/*.yaml`** — conda environment specs for the tools used by rules (26 active envs; bcalm, metaspades, and bbtools were removed as unused)
- **`workflow/profiles/default/config.yaml`** — Slurm executor config for UC Berkeley Savio cluster

## Key constraints

- **This is not a Python package.** There is no `setup.py`, `pyproject.toml`, test suite, linting, or CI.
- **Runs only on Savio HPC.** The profile uses `executor: slurm` with `co_moilab` account and `savio4_htc` partition. Do not attempt to run the full workflow locally. On htc partitions memory must NOT be requested explicitly: Slurm derives job memory from cores at `DefMemPerCPU=4000` MB/core (verified via `scontrol show partition savio4_htc`; 56-core/503 GiB nodes). Size `cpus_per_task` for memory-hungry rules (e.g. `kmate_kmer_db`/`kmate_run` 12 cores -> 48 GB covers the 32G jellyfish hash; with 8 cores the ~32 GiB table OOM-killed the step in 25 s — 2026-10-22). The only sanctioned memory-like key is `vg_autoindex`'s `max_mem: "32G"`, which vg autoindex consumes itself (`-M`), not a `--mem` request.
- **External data is not in the repo.** The `resources/` directory (reference genomes, annotations, CRAM files) is gitignored and must be provisioned separately. Paths in `config.yaml` use `../resources/` relative to `workflow/`.
- **`pool_sizes.csv` is auto-generated** at Snakefile parse time (lines 19-22 of `Snakefile`) from `samples.tsv`. Do not commit or manually edit it.
- **Conda environments are required.** Always use `--use-conda` when running snakemake. BRAKER rules additionally require `--use-singularity` (snakemake auto-pulls `braker_container` from Docker Hub into `.snakemake/singularity/`). The `freqk` binary is NOT conda-managed: it must be placed manually at the path in `config["freqk_binary"]` (`/global/scratch/users/milesroberts/brandvain_lab_projects/lepto/bin/freqk`; grab the Linux release from github.com/milesroberts-123/freqk), like the `msmc2_binary` precedent.
- **BRAKER singularity caveat:** Savio compute nodes have no internet. The first-time container pull must happen on a login node (either via a snakemake run from the login node, or `apptainer pull docker://teambraker/braker3:v3.1.1`); the cached image in `.snakemake/singularity/` is then readable by compute nodes. `sra_download` and `odb_download` (OrthoDB Viridiplantae protein evidence, gated by `config["braker_use_protein"]`) also need internet, so run those rules on a login node with `--local-cores`. Same for `busco_lineage_download` (below).
- **BUSCO annotation completeness** (`busco.smk`, added 2026-10-21) — protein-mode BUSCO (`busco=6.1.0` + seqkit in `envs/busco.yaml`; 6.1.0 because the user's manual env empirically ran it with the version-suffixed lineage name) on every BRAKER3 annotation (wildcards over `braker_refs` = `braker_genomes` keys; just `linanthus` today). Chain: `busco_lineage_download` (`busco --download` of `config["busco_lineage"]` = `eudicotyledons_odb12.2` into `config["busco_downloads_dir"]`; login node like `odb_download`, confirm spelling with `busco --list-datasets`) → `busco_proteins_select` (seqkit `.t1` filter of `braker.aa` → `results/busco/{ref}/busco_proteins_select_{iso}.faa`; representative-isoform convention, TSEBRA t1 ≈ the 39,769 genes) → `busco_proteins` (`-m proteins -c {threads} --offline`, output `results/busco/{ref}/busco_proteins/short_summary.specific.{lineage}.busco_proteins.txt` — the only snakemake-tracked output; lineage name sits in both the out-path and the summary filename per the grenedalf naming lesson). `busco_isoform: "none"` switches the selection pattern to `.` (all transcripts; D inflated by 2,814 extra isoforms). Target: `busco_all`. Manual BUSCO 6.1.0 pre-runs exist untracked under `workflow/busco_{proteins,longest_proteins,downloads}/` — longest-isoform-on-expressed proteome scored C:71.9%[S:63.6%,D:8.2%],F:1.7%,M:26.4%,n:1990 (eudicotyledons_odb12.2) — the canonical t1-on-full-annotation numbers may differ.
- **Sequence tube map** (`tubemap.smk`, added 2026-10-22) — static tube-map-style SVGs of the minimap2 hap2-vs-hap1 alignment (`results/vg/hap2_vs_hap1.vcf.gz` over `results/vg/hap1_prefixed.fasta`), NOT the sequenceTubeMap web app (NodeJS/interactive, unusable headless): per region from `config["tubemap_regions"]` ("chrom:start-end"; chunk wildcard sanitizes to `chrom_start_end`, constrained name-wide in the Snakefile — `{region}` was collision-free at add time) pad by `tubemap_region_pad` → `vg construct -r fasta -v vcf.gz -a -R chrom:start-end | vg index -x` (`-R` does the region slicing natively — no faidx/tabix slicing, and VCF/fasta coordinates line up; a first sliced-fasta draft failed on the local-coordinate mismatch) → `results/tubemap/{variant}_vs_{backbone}/{region}/graph.xg` → `vg viz -x graph.xg --out tube_map.svg`. All offline (`envs/vg.yaml`); fai reused from `msmc2_faidx`. **Regions must be kb-scale** — vg viz draws 1 bp per layout unit (a 70 kb test region rendered a 72245pt × 24pt flat strip, e2e-verified); coordinates inside each rendered graph restart at the region start. Target: `vg_tubemap_all`.
- **Target rules** (entrypoints): `all`, `panther_all`, `orthofinder_all`, `featurecounts_all`, `degenotate_all`, `vg_diversity_all`, `dnds_all`, `sourmash_all`, `msmc2_all`, `svim_all`, `braker_all`, `freqk_all`, `anchorwave_pair_all`, `vigs_all`, `mcscanx_all`, `kmate_all`, `cds_windows_all`, `ldx_all`, `busco_all`, `vg_tubemap_all`.
- **The `.gitignore` is aggressive** — it excludes most bioinformatics file types (`.fastq`, `.bam`, `.fasta`, `.vcf`, `.tsv`, etc.). Be careful when adding new output types.
- **Grenedalf interval filenames embed the window geometry** — `grenedalf_diversity_interval`/`grenedalf_diversity_interval_pooled`/`grenedalf_fst_interval` produce `grenedalf_results_interval_w{wlen}_s{sstep}_*.csv` or `grenedalf_results_pooled_w{wlen}_s{sstep}_diversity.csv` where `wlen`/`sstep` wildcards carry `grenedalf_window_width`/`grenedalf_window_interval_stride` straight from config (the rules' `--window-interval-*` flags and `--file-prefix` come from the wildcards, so filename and analysis parameters cannot drift; `wildcard_constraints: wlen/sstep=[0-9]+` in the Snakefile). Changing those config keys yields new filenames and a rebuild; genome-window outputs stay `grenedalf_results_genome_*` (never suffixed). Anything globbing interval outputs by name must use `interval_.*_(diversity|fst).csv` patterns (Rmd line ~1118 patched accordingly). Naming lesson (2026-10-15): the wildcards were first called `w`/`s`, which broke `snkc -n sourmash_all` — global `wildcard_constraints` apply name-wide across ALL subworkflows, and `{s}`/`{t}` are already taken by `sourmash_mutation_rate` (`mutation_rate_{s}_vs_{t}.txt`); the `[0-9]+` constraint made `s=hap1` unmatchable → MissingInputException. Before introducing a new wildcard name, grep every `.smk` + Snakefile for `{name}` collisions.
- **Session transcripts must be archived before every push.** Run `scripts/export_session.sh` first: it exports the full transcript of the current opencode session as JSON (`opencode export <session-id>`), compresses it with `xz -9` into `transcripts/<session-id>.json.xz` (one file per session, overwritten on each push), and stages it. Commit the staged archive with a `chore:` prefix before pushing; if the script fails, do not push.

## Reverted approaches (do not re-add)

When a tool or subworkflow is reverted, record it here with the reason so it isn't re-added later, and commit the reversion with a `chore:` prefix referencing this section.

- **VIGS BWA-mem off-target scan against whole-genome references** (first draft of `vigs.smk`, never committed) — **replaced before first commit by transcriptome k-mer subtraction; do not re-add.** The initial VIGS design scanned each target's k-mers with `bwa mem` against `config["vigs_offtarget_refs"]` whole-genome fastas plus the non-target CDS with an NM mismatch allowance. The user redirected the design: off-target screening must be against **the rest of the transcriptome only** (a transcriptome fasta + target-ID list in config), with **exact** matching (k=19 ⇒ strict end of the docx 19–21 nt rule; mismatch tolerance would under-reject). Also empirically killed while testing: KMC 3.2.4 silently ignores option flags placed after the `@input-list`/working-dir arguments (only `kmc -k… -ci1 -fm @list …` order works — flags after the working directory ran as k=25 with `ci=2`), `kmc_tools -t8 transform` chokes when the `-t8` is glued to `transform`'s spot in the wrong position, and KMC's input default is FASTQ (`-fm` required for fasta). Consequences: `vigs_offtarget_refs`, `vigs_target_cds`, `vigs_max_mismatch` config keys do not exist; no bwa/samtools/bedtools in `envs/vigs.yaml` (seqkit only; KMC rules reuse `../envs/kmc.yaml`).
- **VIGS KMC k-mer subtraction + awk unitig assembly** (`vigs.smk` before the 2026-10-23 rewrite) — the original chain dumped every non-target k-mer with KMC (`vigs_nontarget_kmers`, both strands via `vigs_nontarget_rc`), filtered target sliding-window k-mers against the set (`vigs_target_kmers`), and ran a consecutive-position run-compressor awk (`vigs_assemble`) over `target_seq.tsv` to cut stretch spans into insert blocks. Superseded first by the unitig-caller swap, then by the KMC-count + bwa-mem map-back design (see the VIGS bullet); **do not re-add** — the map-back formulation is strictly simpler and was fixtures-verified sound.
- **VIGS target design via unitig-caller (Bifrost coloured graphs)** (`vigs.smk` on 2026-10-23, commit e4d6f97; reverted the same day) — **replaced by the KMC + bwa mem map-back chain per user request for simplicity; do not re-add.** It worked and was empirically sound (kept unitigs held 0 shared 19-mers, 0 missing target-unique k-mers on both fixtures), but bloated to 6 rules: unitig-caller colours are per input FILE so each target needed its own graph (`vigs_target_slice`/`vigs_unitig_caller` per `{idx}` + `vigs_concat`), and the tool samples colours only at unitig head/tail and INTERSECTS them, so `vigs_probe` re-checked both endpoint k-mers via `--simple` FM-index and the map trimmed 19 bp behind hits. The endpoint caveat never fired in practice (compaction breaks shared tracts at branch nodes; divergent-side unitigs begin at unique junction k-mers). Findings worth keeping: `{idx}` must be `{wildcards.idx}` in shell strings; Bifrost aborts "Could not create tmp directory" on refs fed via bash process substitution (plain refs files only); `--simple` omits queries found nowhere from its pyseer output (set-membership parsing, not positional).

- **AnchorWave gene-anchored whole-genome alignment** (added 2026-08-31 in 2d75748, switched to prefixed assemblies in e9cedff, removed in 84fa7ec as `chore: remove anchorwave subworkflow`) — **structurally incompatible with this project's hap1/hap2 assemblies; do not re-add.** All AnchorWave v1.3.1 anchor-generation modes (`genoAli`, `minimap2`-based `ali`, and `proali`/Quota-alignment) require the reference and query genomes to share contig names: anchor candidates are only kept when `refChr == queryChr` and the contig name exists in the reference GFF, the reference FASTA, and the query FASTA simultaneously (`src/service/TransferGffWithNucmerResult.cpp`; contigs missing from any of the three name spaces are dropped with "There is not enough anchors found on ..."). With zero surviving anchors the run aborts with "there is no match anchor found in the input sam file". Our hap1/hap2 scaffolds are numbered independently and ordered by length, not by homology — measured directly from the splice SAMs, 0 of 6,098 CDS with primary alignments in both haplotypes landed on same-numbered scaffolds (0.0% name correspondence), so no anchors can ever be constructed, with either raw (`scaffold_N`) or prefixed (`hapN_scaffold_N`) names. Do not re-add anchorwave unless it gains all-by-all scaffold-homology support. For synteny/breakpoint analysis use the existing whole-genome minimap2 alignment instead (`minimap2_asm_paf` in `vg_diversity.smk` → `results/vg/{variant}_vs_{backbone}.paf`). (Related earlier removals: bcalm, metaspades, bbtools conda envs were unused.) **Sanctioned exception (added 2026-09-25, `anchorwave_pair_all` in `anchorwave_pair.smk`):** single scaffold-pair alignments where both scaffolds are explicitly extracted and renamed to a shared name (`anchorwave_pair_common_name`, e.g. `scaffold_pair`) before `genoAli`, satisfying the matching-name requirement by construction. The name mismatch that killed the whole-genome branch cannot occur; keep this pattern (extract → rename → gff2seq → splice SAMs → genoAli) if another pair is needed.
- **freqk grenedalf polymorphic-site exclusion** (added 2026-09-21 in 61499f5, removed 2026-09-22, re-added 2026-09-26 for W-group pools only) — **couples freqk to the vg mapping chain; keep it scoped to W-group samples.** The original `freqk_exclusion_bed` consumed all 8 per-pool `grenedalf_results_frequency.csv` tables to build a BED of sites polymorphic (0.02 < freq < 0.98) in any pool, which `freqk_filter_vcf` excluded with `bcftools view -T ^bed`; it was reverted because adding those CSVs as freqk inputs made any freqk-only target (`snkc -n freqk_all`) schedule the entire vg chain (74+ jobs: samtools_fastq, fastp, vg_giraffe, grenedalf, …) — consumed temp files force upstream rebuilds into the consumer's DAG (verified: `--rulegraph`/`--dag` showed grenedalf→freqk edges; `ancient()` on the CSVs and on `results/fastp/{ID}.fastq` did NOT break the cascade — snakemake 9.16.2 only honors ancient when all such inputs both are ancient AND exist, so missing temps drag consumers regardless; dag.py:1609-1612). The current sanctioned design (2026-09-26) re-adds `freqk_exclusion_bed` but consumes only the 4 W-group (`group == "W"`, `w_sample_ids` in Snakefile) frequency tables, with thresholds as config keys (`freqk_min_alt_count: 1`, `freqk_min_depth: 10`, `freqk_min_polymorphic_freq: 0.02`, `freqk_max_polymorphic_freq: 0.98`; awk `$1 != "CHROM" && $6 > c && $7 >= d && $8 > f && $8 < x`), unioned into a 0-based BED (two-step: `freqk_exclusion_sites` awk-extracts an unsorted temp intermediate, `freqk_exclusion_bed` does `sort -k1,1 -k2,2n | bedtools merge -i -`); `freqk_filter_vcf` pipes `bcftools norm -m -any | bcftools view -T ^bed | bcftools view -i 'QUAL>=…' -v snps -m2 -M2`. Run `vg_diversity_all` first and keep its products; freqk-only targets still schedule the vg chain when the CSVs are missing — do not widen the CSV set (back to all 8 pools or other groups) without re-accepting that tradeoff. `freqk_use_exclusion_filter: false` (added 2026-10-05) drops `freqk_filter_vcf`'s exclusion input and the `-T ^bed` stage, removing `freqk_exclusion_sites`/`freqk_exclusion_bed` and the grenedalf CSVs from the DAG entirely (verified: freqk-only dryrun shrinks 54→14 jobs); norm and the QUAL/biallelic view always run; flip the key (or override `--config freqk_use_exclusion_filter=true`) to re-enable — the persisted BEDs are reused, not rebuilt.

- **MCScanX hap1/hap2 collinearity** (`mcscanx.smk`, added 2026-10-05, fixed 2026-10-18) — consumes the featureCounts-expressed products (`mcscanx_input_fastas`/`mcscanx_input_gffs` in config point at `results/featurecounts/{species}_expressed.faa`/`.gff3`), so `mcscanx_all` schedules the featurecounts chain per species. Gene-ID contract: proteomes filtered to `.t1` transcripts with the suffix stripped, then prefixed `hapN.` on gene **and** scaffold names (scaffold numbering collides between haplotypes — prefixing is mandatory); BLAST hit names equal the 4-column GFF gene names by construction. Because featureCounts runs `-g Parent` (counts/glist are transcript-level `gN.tM`), the expressed GFF3 subset has **no `gene` rows** — `mcscanx_gff_to_4col` therefore consumes the `mRNA` rows instead: only `.t1` transcripts (same representative rule as the proteomes) with the suffix stripped (transcript span stands in for the absent gene span; a gene with no expressed t1 yields no GFF row), and `mcscanx_concat_gffs` reorders the gene-first 4-column output into MCScanX's required chr-first form (`chr, gene, start, end`). Chain: t1+prefix -> concat faa/gff -> `makeblastdb` (envs/blast.yaml, blast 2.16.0; db referenced via the concrete `leptosiphon.phr` product because `directory()` is invalid as an input flag) -> all-vs-all `blastp -outfmt 6` -> `results/mcscanx/leptosiphon_all.blast` (`mcscanx_blast_evalue`/`mcscanx_blast_max_targets`) -> `MCScanX` in `results/mcscanx/collinearity/` (bioconda `mcscanx=1.0.0` in envs/mcscanx.yaml with seqkit; MCScanX needs `<prefix>.blast`+`.gff` sharing a basename in its cwd — the binary reads `%s.blast` only (string-table-verified), no `.hom` fallback — and writes `.collinearity`, `.tandem`, `.html/` next to the input prefix; a collinearity file that is just the parameter header means zero gene names matched). MCScanX is single-threaded; only `mcscanx_blastp` uses set-threads. Shell-string gotcha (2026-10-18, was a hard Snakefile SyntaxError): awk program braces must be doubled (`{{...}}`) in every snakemake shell string, and awk snippets belong inside triple-quoted (`"""`) shell blocks — inner double quotes in a plain string literal terminate the Python string and break the entire Snakefile parse.

- **kMate pink-pool allele frequencies** (`kmate.smk`, added 2026-10-05) — alignment-free haplotype-mixture estimates for the P-group pools (config `kmate_groups`, ids via `p_sample_ids` in the Snakefile). The panel is built from freqk's upstream `results/vg/{variant}_vs_{backbone}.vcf.gz` (NOT freqk's `norm.vcf.gz`, and WITHOUT the `-v snps` cut — indels stay in), haploidized with an all-reference `hap1` backbone column (GT=0 everywhere) plus the `hap2` variant column (GT=1 everywhere), bgzip+tabix — a 2-founder panel, so `kmate_min_ac: 1` is mandatory (the production filter drops ac<min-ac and ac>F-1; with F=2 and defaults the matrix is empty — verified e2e). kMate REQUIRES exactly one `--chroms` value per `kmate run` invocation (`--var-pa-prefix` is per-chromosome), so the chain is per-chrom: checkpoint `kmate_build_index` (`directory()` output; re-expansion discovers `<chrom>_kmers.tsv.gz`) -> `kmate_build_kmer_pa`/`kmate_build_var_pa` per chrom -> `kmate_kmer_db` (count-once jellyfish DB per pool, `temp()`, deleted at `kmate_concat`) -> `kmate_run` per pool×chrom -> `kmate_concat` (per-pool TSV, `kmate_all` target). Panel VCF exclusion follows the `freqk_use_exclusion_filter` toggle via dedicated `kmate_exclusion_input`/`kmate_exclusion_stage` helpers. Conda env gotcha: bioconda `kmate=0.1.2` declares `python>=3.8` but its `dna_jellyfish` dependency is a py3.10 C extension — on 3.14 imports fail with ModuleNotFoundError; envs/kmate.yaml pins `python=3.10` (selftest PASS verified locally, plus an e2e synthetic run: AF 0.203 vs truth 0.2, identical AFs via `--kmer-db` count-once path). `kmate_hash_size: 32G` for the 456 GB pool-1 fastq; wiki warns shared-filesystem jf DB reads are slow at scale (accepted at 4 pools). kmate-only targets schedule the whole vg chain whenever upstream products are missing — run `vg_diversity_all` first. **Production runs failed twice (2026-10-22) and both fixes are in:** (1) `kmate_kmer_db` OOM — jellyfish allocates the whole `-s 32G` hash upfront, **measured 163.5 GB MaxRSS** (`/usr/bin/time -v` probe, 2³⁵ entries at ~4.8 B/entry, grows toward ~5.4 B/entry at smaller table sizes; the memory is core-derived on htc, see Key constraints — OOM'd in order at 32 GB (8 cores, 25 s, misleading `Broken pipe` from `zcat`), 48 GB (12 cores, 13 s), 125 GiB (32 cores, 15 s), and 160 GB (40-core probe) — current value 48 cores = 192 GB; `-s 16G` fallback would need ~32 cores for its 92.3 GB table at the cost of hash-full risk); (2) `kmate_build_index` ValueError `start (2714027) > stop (2714026)` — kmate's bubble machinery assumes non-overlapping REF spans and pysam raises on the inverted `fetch(chrom, v.end, next.start)`; the paf-derived panel has 1,831 same-POS ins+del pairs (repeat tracts) among 10.5 M records plus 1 record within k-1 of a scaffold head, so `kmate_panel_vcf` gained a keep-first overlap filter + POS ≤ k-1 head guard (drops ~0.02% of records; fixture-verified e2e: control reproduces the exact pysam ValueError, deduped panel builds the full index). awk gotcha re-learned: input lines matching NO rule print NOTHING (no implicit print) — header lines need their own `/^#/ {print; next}` rule or the panel ships headerless (`n_samples=None` TypeError downstream).

- **CDS bases per genome window** (`cds_windows.smk`, added 2026-10-15) — upstream-free branch producing `results/cds_windows/cds_windows_w{wlen}.bed` (`chrom start end cds_bases`), from a single assembly fasta + matching GFF3 chosen by hand in config (`cds_windows_fasta`/`cds_windows_gff3`/`cds_windows_sizes` list; defaults point at the hap1 pair, repoint freely). The window width rides the `wlen` wildcard into the output filename (grenedalf interval naming pattern, same global `[0-9]+` constraint — bedtools `-w {wildcards.wlen}`, so filename and geometry cannot drift) and results for different sizes coexist; `cds_windows_all` expands over the list. Chain: `samtools faidx --fai-idx` (`envs/cds_windows.yaml`, bedtools 2.31.1 + samtools 1.24; the `--fai-idx` redirect keeps the index out of `resources/` and requires samtools ≥ 1.10) → GFF3 CDS extraction (`$3=="CDS"`, 1-based→0-based half-open) sorted + `bedtools merge` (isoform-overlapping CDS unioned, each base counted once; book-ended CDS also merged) → `bedtools makewindows -w wlen | bedtools coverage -a - -b cds | awk` (coverage col 5 = bases in window covered by CDS — e2e-verified with overlapping-isoform and book-ended fixtures; makewindows emits a short trailing window per scaffold; all windows kept, zeros included). Faidx + cds.merged.bed intermediates are window-independent (shared across sizes); three single-tag rules plus the {wlen}-carrying final rule, no upstream deps, so `cds_windows_all` runs anywhere (`snkc -n cds_windows_all`).
- **VIGS target design via KMC + bwa mem map-back** (`vigs.smk`, rewritten 2026-10-23 twice: unitig-caller swap reverted same day for rule-count bloat; the user specified the final shape: three rules max) — isolate the chosen target records (`vigs_target`, seqkit grep with empty/duplicate/missing-ID guards; the non-target fasta is gone, the whole transcriptome is the map reference) → count the targets' distinct k-mers with KMC (`vigs_kmers`, `kmc -k{vigs_k} -sm -ci1 -fm`; **the KMC working directory must pre-exist** — `mkdir -p .kmc_tmp` or it aborts "Cannot create file in specified working directory") → map them back with bwa mem (`vigs_map`: `bwa index -p results/vigs/.idx <transcriptome>` — the `-p` prefix keeps index files out of `resources/`, all rm'd in-rule after the run) and one awk that keeps k-mers whose complete set of reported loci lies inside the chosen target IDs (IDs read from target.fasta headers in-awk; bwa QNAME = the k-mer sequence itself, so the SAM keys alignments back to k-mers with zero side tables) and compresses surviving positions into maximal runs — one row per stretch in `results/vigs/vigs_stretches.tsv` (`target stretch_start stretch_end length gc`, header printf'd once). Soundness is load-bearing on two bwa flags: **`-T {vigs_k}`** (on k-nt queries any mismatch drops the score below threshold, so every reported alignment is a full-length exact match) and **`-a`** (every locus reported as its own record, reverse-strand hits included — fixture-verified: a shared k-mer shows primary + secondary records on two rnames). Fixtures-verified (shared 150 bp pads verbatim in a non-target, a 60 bp SEG whose RC sits in another non-target, a 220 bp B-repeat across two chosen targets): T1 recovered exactly its two known unique bp spans, T2 its full-unique record, B correctly attributed in BOTH transcripts from one bwa run. No snakemake e2e run (user skipped). - **LDx pooled LD** (`ldx.smk`, added 2026-10-19) — linkage disequilibrium (r²) from pool-seq alignments (Feder, Petrov & Bergland 2012, PLoS ONE 7(11):e48588, doi 10.1371/journal.pone.0048588): short-range 2-locus haplotype tables from reads intersecting SNP pairs (same read or read pair), "direct" r² from the table + approximate-MLE r² anchored to all-read allele frequencies, CIs ±1.92 LL units on a 0.01 grid. Chain: checkpoint `ldx_scaffold_list` (from the backbone prefixed dict @SQ lines; `checkpoints.…get()` re-expansion, kmate pattern) → per pool `ldx_depth_mean` (mean of grenedalf frequency CSV col 7) + `ldx_snplist` (from the SAME per-pool grenedalf frequency CSV: col1 CHROM, col2 POS, depth col 7 ≥ `ldx_snplist_min_depth`, 0 < alt freq col 8 < 1; sorted `chrom\tPOS`) → per (pool, scaffold) `ldx_slice` (temp: `samtools view -F 0x904 -q {ldx_min_mapq}` on the persistent `{ID}.bam` — LDx ignores SAM flags, so unmapped/secondary/supplementary must be pre-filtered — plus the scaffold's two-column snp rows) → `ldx_run` (`perl {ldx_binary} -l -h -s -q -a -i slice.sam snps.txt`, system Perl, NO conda; binary provisioned outside the repo via `config["ldx_binary"]`, freqk precedent: `curl -L -o bin/LDx.pl https://sourceforge.net/projects/ldx/files/LDx.pl/download` on a login node) → `ldx_merge` (cat of `{ID}.{scaffold}.pairs.tsv` → `{ID}.ldx_pairs.tsv`; `ldx_all` target over all sample_ids). **LDx parsing contracts (nearly shipped a bug):** it `split("\t")`s every snplist line and pushes ONLY field 2 (POS) — CHROM ignored — so snp inputs must be TWO-COLUMN (a single-column `cut -f2` position list is invisible to it) and a run MUST pair a single-scaffold SAM slice with the same-scaffold snp rows, else reads/positions cross-match between scaffolds; all options come BEFORE the two positional files, `-h` is the MAXIMUM site depth (repeat/paralog guard), not help, and site depth is kept only for `l < depth < h` while `-i` is strictly greater (11 ⇒ 12+ shared reads). Adaptive thresholds per pool from `depth_mean.txt`: `-l = max(floor 10, mean/8)`, `-h = 2 × mean` (paper's 10..100 at 40×). Output rows (no header, scaffold-tagged to 20 cols): `scaffold POS1 POS2 x11 x12 x21 x22 PA PB d1 d2 shared r2_mle_lo r2_mle r2_mle_hi r2_direct A a B b`. Quirks verified locally: the `freq` hash stores MAJOR frequencies (`$maf = max(PA, 1-PA)` despite the name) so printed PA/PB and the MLE are major-coded like the table, but haplotype cell labels `A/a B/b` and the x-column order follow WHICHEVER shared read the perl hash-order picks first (row/col flips only on strict margins) — exact-0.5/0.5 sites can leave the MLE orientation-fragile (its D is `sqrt(·)`, non-negative only, so a negatively-associated labeling collapses to 0), whereas the direct r² column is orientation/sign-free and matched independent recomputation to 1e-6 — treat `r2_direct` as primary. Mates share a read name by design (that is the cross-mate haplotype link; the later mate overwrites the first at shared SNPs). Consuming the `{ID}.bam`s and grenedalf CSVs couples ldx targets to the vg chain when those products are missing (run `vg_diversity_all` first, freqk/kmate acceptance). Verification: 6-check synthetic fixture suite (hand-computed tables incl. the unsliced cross-scaffold trap) + the canonical example dataset (SourceForge `2R_short.txt`: simulated 20× pooled DGRP reads around SNPs 2R:12121353/12121380) run through the real snakemake DAG end to end — 48 pairs, canonical row r²_direct = r²_mle = 0.81, CI [0.36, 0.98].
