# McDonald-Kreitman tests and memory design

Moved out of AGENTS.md on 2026-11-19 to keep per-turn context small. Content is verbatim.

- **McDonald-Kreitman tests** (`mk.smk`, added 2026-11-13) — standard MK per gene: Dn/Ds from codon alignments of 1:1 orthologs (ingroup `mk_ingroup`=hap1, outgroup `mk_outgroup`=linanthus), Pn/Ps from the per-pool grenedalf frequency CSVs classified with `results/degenotate/hap1/degeneracy-{zero,four}-sites.bed` (0-fold = nonsyn, 4-fold = syn, 2-fold dropped). Chain: `mk_ortholog_pairs` (OrthoFinder `Orthogroups.tsv` → 1:1 .t1 pairs; species columns = config keys, IDs stripped of the `<species>.` prefix) → `mk_cds_extract` per species (pysam; `.t1` CDS from `<species>.gff3` + genome fasta, plus a CDS-position→genome map used to project codon columns back to hap1 coords) → `mk_codon_align` (MAFFT proteins + pal2nal codons, `xargs -P {threads}` per orthogroup; failures recorded as `<og>.failed` in the output directory) → `mk_polymorphism` (grenedalf `grenedalf_results_frequency.csv` positional contract: col1 CHROM, col2 POS, col6 ALT count, col7 depth, col8 ALT freq — same as ldx.smk/freqk.smk; polymorphic = depth ≥ `mk_min_depth`, alt count ≥ `mk_min_alt_count`, 0 < freq < 1; per-pool tables + pooled union + `polymorphic_sites.tsv`) → `mk_divergence` (codon-alignment fixed differences; codons with a gap/stop skipped and codons carrying a site polymorphic in any pool excluded — shared polymorphism is not divergence; multi-change codons scored by averaged minimum-replacement paths, fractional Dn/Ds) → `mk_codeml` (PAML `runmode=-2` pairwise per ortholog, stops/frameshifts reported not run) → `mk_stats` (alpha = 1 − Ds·Pn/(Dn·Ps), NI, DoS, two-sided Fisher exact on rounded integer counts + BH per pool). Consumes the vg grenedalf CSVs, so `mk_all` schedules the vg chain when those are missing (run `vg_diversity_all` first, freqk/kmate acceptance). **OrthoFinder path casing (2026-11-13):** OrthoFinder itself creates `results/orthofinder/proteomes/OrthoFinder/Results_<date>/` — capital F in `OrthoFinder`, with the actual results one level deeper in a date-named `Results_*` directory. An earlier lowercase `Orthofinder` output path never existed on disk, which made every consumer look like a missing dependency (snakemake "wanted to re-run" OrthoFinder). The declared output is now that exact directory and `mk_ortholog_pairs` resolves the newest `Results_*/Orthogroups/Orthogroups.tsv` (also accepts a flattened `Orthogroups/Orthogroups.tsv`). The former duplicate staging rules were also consolidated: `orthofinder_stage_external` is gone, `orthofinder_stage` now takes either `results/orthofinder/prefixed/<species>.faa` or `orthofinder_external_proteomes[species]` via one input lambda — with two rules on one output path, the external rule's `[...]` lookup raised `KeyError: 'hap1'` whenever snakemake evaluated it (fatal for consumers under snakemake 9.27, warning-only under 9.16).

- **mk_polymorphism memory design (2026-11-13)** — the first version OOM'd on Savio: it built three string-keyed containers (`zero`/`four` BED sets, `index` dict of `chrom:pos` → tuple, and a `cds_sites` set) at ~90 B/site, ~15-20 GB at this annotation's ~40-60 M CDS sites, before reading any pool CSV. Now: per-scaffold sorted `array('q')` position vectors with parallel `array('B')` class and `array('i')` gene-id arrays, bisect lookups, index held as ~20 B/site (measured 7.6x lower peak RSS on a 5 M-site synthetic map: 1350 MB → 178 MB; outputs byte-identical to the old implementation). Upstream, `mk_frequency_filter` streams each pool's genome-wide `grenedalf_results_frequency.csv` (written with `--write-invariants`, so ~10^8-10^9 rows) through awk — same thresholds (`mk_min_depth`, `mk_min_alt_count`), constant memory, C speed — into temp `results/mk/frequency/{ID}_polymorphic.csv` (5 cols: chrom,pos,alt,depth,freq, no header). `mk_polymorphism` accepts either that extract or the raw 8-column CSV (col1 CHROM, col2 POS, col6 ALT count, col7 depth, col8 ALT freq), so both paths give identical counts. Net effect: `mk_polymorphism` is back down to `cpus_per_task: 2` (8 GB derived) with the awk pass at 1 core. New env `envs/mk.yaml` (python + pysam) for the counting scripts; alignment/codeml reuse `envs/paml.yaml` (mafft + paml + pal2nal). **Annotation source (2026-11-15):** `mk_species_annotations` must point at the **expressed** GFF3s — `results/featurecounts/hap1_expressed.gff3` and `results/braker/linanthus/braker_expressed.gff3`, the same annotations the proteomes came from. Pointing at the unfiltered `resources/annotation/hap1.gff3` (280k BRAKER gene models vs 39.7k expressed) made the CDS disagree with the `_expressed.faa` proteins, so pal2nal failed on 3,779 of 5,196 pairs and the CDS map ballooned to 412 M positions / 16 GB. **Pn/Ps classification (2026-11-18):** by translation, not degeneracy. No degenotate dependency: `mk_frequency_filter` carries REF/ALT through (`chrom,pos,ref,alt,alt_count,depth,freq`), and `mk_polymorphism` builds each site's codon from the CDS, substitutes the ALT base, and counts Ps when the amino acid is unchanged (stop-gain = Pn). 2-fold sites therefore count, classified by the observed allele. Memory is indexed on polymorphic sites only: per-scaffold numpy position vectors + 1 B allele code for the pool union, the map streamed once to classify, then a second pass over the pool tables (measured 235 MB peak for 8 M union sites on a 20 M-row map). **Multi-allelic positions** (same position, different ALT in different pools) are dropped from Pn/Ps but stay in `polymorphic_sites.tsv`, so divergence still excludes that codon. **mk_divergence memory (2026-11-15):** the first version loaded the whole map into a dict of `(cdspos, chrom, pos)` tuples and was OOM-killed at 8 GB on the real map. It now streams the map once in transcript blocks, keeping only the block whose transcript has an alignment, and holds the polymorphic-site set as per-scaffold sorted `array('q')` vectors with bisect. Measured on a 20 M-position map: 3,651 MB → 16 MB peak RSS (221x), outputs byte-identical; memory is independent of map size. **Minus-strand CDS bug (2026-11-15, fixed 2026-11-18):** `mk_extract_cds` sorted minus-strand exons in transcript order (descending) and then reverse-complemented the joined plus-strand segments, which reverses exon order — every minus-strand multi-exon gene came out scrambled, pal2nal failed on 3,793 of 5,196 pairs, and only single-exon/plus-strand genes aligned (1,403). Correct: complement each exon separately. The regression fixture now includes a minus-strand two-exon gene; the earlier fixture only had a single-exon minus gene, which is why the test passed. `envs/paml.yaml` must carry an explicit `python` (now 3.12) because `mk_codon_align` and `mk_codeml` run `python3 scripts/mk_*.py` inside that env — without it the shell fell through to the Savio OS python 3.6 and died on 3.7+ APIs (`subprocess.run(capture_output=...)` → `TypeError`, first observed 2026-11-13 in the `mk_codon_align` slurm log). Those two scripts now also use `stdout=PIPE, universal_newlines=True` instead of `capture_output/text` so they stay 3.6-safe; keep that pattern in anything executed by a rule whose conda env lacks python. `mk_stats.py` uses `math.comb`/walrus and therefore requires ≥3.8 — it runs in `envs/mk.yaml`, not here. Scripts live in `workflow/scripts/mk_*.py`; note the Snakemake shell runs with cwd = `workflow/`, hence `scripts/...` paths.
